# M3 照応詞チェック：発明種類宣言と先行詞唯一性の問題

作成: 2026-05-04

---

## 背景

日本の特許クレームは末尾に発明種類を宣言する（「…を有する**水陸両用自動車**。」）。
この末尾名詞は `前記` なしで出現するため、`_collect_defined_nouns` が先行詞候補プールに収集する。
複数の請求項にまたがると同一名詞が重複登録され、下位請求項の「前記X」の唯一性が形式的に崩れる。

---

## 「であって」を使わない実務スタイルとの関係

EPO のプリアンブル認定（前置き部分／特徴部の分割）を避けるため、
従属クレームの冒頭に「請求項１に記載のＸＸ**であって**、」と書かないスタイルがある。

このとき冒頭の引用句が先行詞を置かないため、
「前記XX」の先行詞は**祖先請求項の末尾宣言**に依存することになる。

---

## 唯一性が崩れる仕組み

```
請求項１：検知部を有する水陸両用自動車。        ← 「水陸両用自動車」① 末尾宣言
請求項２：前記水陸両用自動車は推進部をさらに有する、
          請求項１に記載の水陸両用自動車。       ← 「水陸両用自動車」② 末尾宣言
請求項３：前記水陸両用自動車は……               ← どれを指す？
```

請求項３のスコープ（請求項１＋２の全文）には「前記なし」の「水陸両用自動車」が①②の２つ存在する。
JPO 実務・審査・裁判所はいずれも「同一エンティティの再言明」として読むため拒絶理由にはならないが、
形式的な多重登録であることは否めない。

---

## 実害が出る場面：発明種類名 ＝ 部品名が衝突するケース

```
請求項１：車両に搭載された車両制御部を有する車両。
請求項２：前記車両は……請求項１に記載の車両。
請求項３：前記車両における前記車両制御部は……
```

「車両」が発明種類かつ「車両制御部」という複合語の構成要素（部品名）を兼ねている。
スコープ内に非前記「車両」が複数出現し、「前記車両」の指示対象が曖昧になる。
これが唯一性崩壊として実害を生じさせる最も典型的な場面。

---

## 発明種類宣言を先行詞候補から除外することの問題点

### 問題１：判定精度

`extract_invention_type()`（`parser.py`）は末尾の正規表現で発明種類を取得するが、
方法クレーム（「水陸両用自動車の**制御方法**」）・複合語の境界で誤判定しうる。

### 問題２：除外すると偽陽性が増える

```
請求項１：検知部を有する水陸両用自動車。
請求項２：前記水陸両用自動車の推進部は……請求項１に記載の水陸両用自動車。
```

請求項２の「前記水陸両用自動車」の先行詞は現状では請求項１末尾の「水陸両用自動車」。
除外するとスコープから消え、エラーの誤報（偽陽性）になる。

### 問題３：末尾宣言は「新インスタンス導入」ではない

発明種類宣言は「この請求項の指示対象はXだ」という宣言であり、
新たなエンティティを導入する記述とは性格が異なる。
実害は発明種類名と部品名が一致する稀なケースに限られる。

---

## checker への実装方針（暫定）

| 対応案 | メリット | 問題 |
|--------|----------|------|
| 除外する | 唯一性確保・スコープ明確化 | 偽陽性増加・判定誤り |
| 除外しない（現状） | 偽陽性なし | 唯一性検出できない |
| 除外せず uniqueness warning 追加 | 最も正確 | 実装コスト・JPO実務では過検出になりやすい |

発明種類名と部品名が衝突するケースは稀であり、**当面は現状維持（除外しない）**。
uniqueness warning は将来の拡張候補とする。

---

## note 記事への展開（案）

「前記」照応の唯一性は特許明細書品質の根幹だが、
発明種類宣言という慣用形式が形式的な多重登録を生んでいることはあまり意識されていない。
「唯一性の崩壊がなぜ起きるか」→「発明種類宣言の二重性」→「"であって"の功罪」
という流れで論じると実務家に刺さりやすい。
