# 「前記」の理論：M3 がこう動く理由

meisai-checker の M3（前記・上記・当該の照応チェック）は、個別の誤検知を潰していった結果として動いているのではなく、一つの考え方から導いた規則で動いています。この文書は、その考え方と、規則ごとの根拠を書いたものです。

「このツールはこう言うが、なぜか」に答えるための文書なので、実装の詳細ではなく、**立場とその理由**を中心に書いています。個々の判定は、[検証用ケース表](zenshou_case_table.md)（43件）で、例文ごとに確認できます。

> **位置づけ**：ここに書いたのは、法令や審査基準が定めたものではなく、「照応詞を持つクレームを言語として整合的に読む」ための作者の立場です。審査実務は、ここに書いた規則より緩く運用されているものが多くあります。その差は[実務との関係](#実務との関係)に書きました。警告は「審査で拒絶される」という予言ではなく、「読み手に複数の解釈を許す書き方になっている」という指摘です。

## 中心原則

> **「前記」の中身は、先行詞の内容であって、導入という行為ではない。**

日本語のクレームには冠詞がありません。そのため、名詞が「新しい対象を導入する」のか「すでに導入された対象を参照する」のかは、位置と「前記」だけで決まります。

- 導入：「端末と、サーバとを備え、」の「端末」。
- 参照：「前記端末は、」の「端末」。

「前記」は参照の行為で、既出の一つの対象を指します。この性質から、次の三つが導かれます。

1. 一つの名詞句で、導入と参照は両立しない。
2. 参照の中身は、先行詞が持っていた内容（名前・数・識別）を超えてはならない。
3. 短縮して参照するときは、どの先行詞を指すかが一意に定まらなければならない。

以下の規則は、この三つの適用です。

## 修飾語の六つの範疇

「前記」の直後に来る修飾語は、働きによって六つに分かれます。

| 範疇 | 例 | 前記の直後 | 理由 |
|---|---|---|---|
| 導入子 | ある・或る・何らかの・いずれかの | 置けない | 導入の行為だけで、保存すべき内容がない |
| 数 | 複数の | 保存する | 既定値（単数）から外れた数は内容。落とせない |
| 量化子 | 全ての・各・それぞれの | 非推奨 | 量化する集合（ドメイン）を、先行詞の数に頼る |
| 識別 | 第Nの・一の（対比あり）・他の・一方の・他方の | 弁別に必要なら保存 | 同じ名詞の他の要素と区別する働き |
| 記述 | 所定の・高温の・受信した・新たな | 保存しても省いてもよい | 弁別されていれば落とせる。先行詞に無ければ足せない |
| 後付け | 先行詞に無い修飾 | 置けない | 再絞り込み禁止 |

## 規則と根拠

### R1：導入子は「前記」の直後に置けない（A1〜A4）

「前記あるタイミング」は、英語で言えば "the a certain timing" です。「前記」は既出の対象を指し、「ある」は新しい対象を導入します。一つの名詞句で両方を行うことはできません。

- 「ある」は、どの文脈でも内容を持たず、導入の行為だけです。したがって、先行詞が「あるタイミング」であっても、「前記あるタイミング」と繰り返すことはできません。
- 部分選択のつもりなら、導入と参照を分解します。「前記複数のタイミングのうちのあるタイミング」。
- 「所定の」は、導入子ではありません。「所定」は「定められた」の意の形容詞で、英語の predetermined に近く、冠詞ではありません。冠詞に当たるのは、初出位置の裸名詞です。

判定は、トークンではなく本文の文字列で行っています。形態素解析が「前記ある」の「ある」を動詞と誤判定するためです。

### R2：数は、既定値から外れる場合に内容になる（B1〜B5）

日本語の名詞は数に中立ですが、「前記」は確定記述（唯一の対象を指す）なので、裸の「端末」は単数側に偏って読まれます。

- 「複数の端末」と導入した後の裸の「前記端末」は、単数の端末を指すことになり、先行詞の数と合いません。群を指すなら「前記複数の端末」と書きます。
- 逆に、単数は既定値なので、「一の端末」の後の「前記端末」は、数が保存されていなくても構いません。

実務では「複数の端末を備え、前記端末は…」と書かれることが多くあります。しかしこの書き方では、「複数のうちのどれか」「全部」「群として」のどれなのか、読み手が補って読むことになります。

### R3：量化は、集合を明示して後置するのが正しい形（C1〜C8）

全称量化（全ての・各・それぞれ）は、複数の要素からなる集合を前提とします。

- 先行詞が**単数**のとき、「前記各N」「前記全ての／すべての／それぞれのN」は、量化する集合がありません。**warning** にします。
- 先行詞が**複数**のとき、「前記各N」「前記全ての／すべての／それぞれのN」は、参照と量化が同じ名詞を取り合い、集合が句の中で明示されません。論理矛盾ではなく起草上の非推奨なので、**info** にします。
- 正しい形は、集合を明示した「前記複数のNのそれぞれ」「前記複数のNの全て」「前記複数のNのうちの各N」です。
- 「各前記N」は、定記述で単数を選んだ後に分配をかける形で、分配が空回りします（既存の警告）。

### R4：後付けの修飾は、出来事に支えられていなければ足せない（F1〜F4）

「前記受信したデータ」のように、「前記」の中に修飾が入ると、記述照応詞になります。

- 修飾が、先行する出来事（データを受信し、…前記受信したデータ）に支えられている、または全文の繰り返し（受信したデータを…前記受信したデータ）の場合は、**info** です。先行詞に解決したうえで、名称化を提案します。
- 支えのない修飾（データを保持し、…前記受信したデータ）は、先行詞に無い限定を「前記」の中で足しています。**warning**（再絞り込み禁止）です。
- 形容動詞の修飾（前記新たなデータ、前記高精度な処理部）は、出来事に支えられないので、先行詞に同じ修飾が無ければ、常に warning です。

「記述は名前になれない」というのが、この規則の背景にある考え方です。説明（記述）は、名前（固有の名称）と違って、同一性を保証しません。

### R5：序数は、区別できないことの宣言である（D1〜D4）

序数（第１の・第２の）を付けた時点で、書き手は「裸の名詞だけでは区別できない」と宣言しています。したがって、「第１のデータ」を受けられるのは「前記第１のデータ」だけで、「前記データ」は不明確です。同じ名詞を持つ他の要素が実際にあるかどうかは問いません。

### R6：識別語を省いた短縮形は、候補が一意でなければならない（B7〜B9、E1〜E8）

「前記N」が完全一致する定義名を持たないとき、識別語（所定の・一の・他の・第Nの）を省いた短縮形として扱います。このとき、先行詞の候補が二つ以上あると、どれを指すか定まりません（**warning**）。

- 候補は、「X＋の＋N」（Xは識別語・限定詞）の形の定義名と、定義構文「Nである呼称」の呼称です。
- 序数付きの名詞は、**照応の解決先にはなりません**（R5）が、**競合には数えます**。
- 全文の繰り返し（前記一の端末、前記所定のタイミング）は、常に一意に定まるので OK です。
- **「一の」の二つの用法**：数としての「一の」（対比相手なし）は、既定値の単数の明示で、冗長だが無害です。対比相手のある「一の」（一の端末と他の端末）は、「一方の」に近い識別ラベルで、保存が必要です。「他の」は、基準となる一つを前提に、残りを指します。
- **複合語は新しい名前です**。「携帯端末」と「端末」が並存しても、それぞれ独立した名前として解決するので、「前記端末」は端末、「前記携帯端末」は携帯端末を指します。複合語の内部（高温｜状態）では切りません。
- 群として導入済みの名詞は、既存の群先行警告に任せます。参照時点より後に導入される呼称は、候補にしません。

## 当該・該について

「当該」は、同一請求項内の局所参照です。導入子の禁止（R1）と記述照応詞の通知（R4）は「当該」にも適用しますが、それ以外の規則（R2・R3・R5・R6）は「前記」「上記」だけを対象としています。

## 実務との関係

- 日本の審査では、明確性は「当業者が文脈から一義的に解釈できるか」で判断されます。ここに書いた規則の多くは、文脈から意図が読み取れるクレームで、拒絶理由にならずに通っています。
- 米国の実務（MPEP 2173.05(e)）も、機能基準（先行詞が一義的に特定できるか）で、文言の完全一致は求めません。英語は冠詞 "the" が参照を担うので、修飾語をどこまで繰り返すかという問題が目立ちません。日本語の「前記＋名詞句」という構文が、この問題を先鋭化させています。
- 実例は、実在性の根拠であって、正しさの証明ではありません。たとえば、JP4748819B2 の請求項1は、「一の端末および他の端末」と「前記一の端末」「当該他の端末」を対にして使い、「前記複数の端末のそれぞれ」という正しい形を使っています。同時に、先行詞が「複数の端末」である裸の「前記端末」も、同じ請求項に混在しています。
- そのため、警告の強さは三段階に分けています。**warning**（読み手に複数の解釈を許す）、**info**（非推奨・名称化の提案）、**通知なし**（実務で通用し、誤検知の恐れが大きい）。

## この文書が扱わないこと

- 請求の範囲の解釈（「端末」が「携帯端末」を包含するか、など）。
- 図面との対応（符号）。M4 の領域です。
- 構成要件参照型の検出。「前記一次捏ね工程で得られた生地」のように、名前を持つ構成要件を先行詞とし、動的な対象を関係節で記述する書き方は、本文書の範疇では正当と扱いますが、積極的に推奨する検査は、まだ実装していません。
